# Tab 背包与 BOSS 自由镜头修复

2026-10-13，Unity 6000.6.2f1，基线 `aead761`。本次修改留在本地工作区，未提交或推送 GitHub。原有 `milkfrog.slnx` 修改和 `Standalone-Startup.log.meta` 未改动。

- MVP 背包从 B 改为 Tab，Tab 再次按下关闭，Esc 返回；长按不重复切换。中键仍用于普通目标锁定。界面提示和 README 同步更新。
- BOSS 战的攻击目标锁定、角色朝向、距离取景与镜头避障保留。镜头的 yaw／pitch 由鼠标输入决定，不再屏蔽输入，也不再每帧强制对准 BOSS。暂停／背包仍冻结镜头，恢复后继续正常转动。
- 原双人训练场的 Tab 锁定操作保持原有行为，该场景没有背包入口。

为验证本次两项操作，在**隔离副本的测试夹具**中用 `LogAssert.Expect` 显式登记三个已确认的旧轨迹初始化错误，然后只运行这两项定向用例。没有在生产代码或正式测试中屏蔽错误，也没有全局忽略日志。这两个用例通过只证明本次操作修复；角色攻击判定仍需单独修复。

曾尝试使用已有烘焙器修复派生轨迹，但新角色是通用骨架，工具调用 Humanoid 骨骼接口时失败。此次没有改变角色、动画、攻击数值或轨迹资产，没有保留该尝试的临时工具／资产。

隔离项目为 `Builds/TabBossCameraValidation/Project`。原项目没有启动 Unity，没有操作真实玩家存档，也没有使用 Computer Use。首次受限启动无法连接本机 Package Manager，随后获准在隔离副本运行批处理。原始 XML 位于本目录；完整日志保留在 `Builds/TabBossCameraValidation`。

## 试玩

运行 `Builds/MilkfrogMVP-TabBossCamera/MilkfrogMVP.exe`，保留同目录 Data、UnityPlayer.dll 和字体许可证。

1. Tab 打开，再按 Tab 关闭；长按保持当前状态。B 不再打开背包。关闭后的菜单点击不会触发攻击。
2. 进入 BOSS 战，左右／上下移动鼠标，确认能绕角色观察、能转离 BOSS，停下鼠标不会自动转回。
3. BOSS 战中用 Tab 打开背包，确认战斗和镜头冻结；关闭后镜头恢复转动。用 Esc 及暂停菜单重复检查。

真人键鼠手感尚未验收。新角色攻击轨迹与训练场旧失败为独立后续工作。
